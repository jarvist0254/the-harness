# Compiler-only completion adapter specification

ROOT design decision: a synchronous, pinned CMake configure/build root returning zero establishes compiler-root completion. Resident compiler telemetry/PDB auxiliaries may then be terminated through that root's owned Job. This is a distinct completion policy, not natural whole-tree completion. Original supervisor files, failed receipts, source and system installation stay unchanged.

Actual diagnostic evidence: attempt4 configure root returned zero after successful generation, but owned Job membership retained vctip.exe and mspdbsrv.exe. The existing supervisor correctly returned TIMEOUT under its natural-drain policy. Twenty-three complete typed samples observed both members; final cleanup killed the owned Job, recorded active zero and CLEANUP. No names-based process control occurred.

Implement a small side-effect-free Python adapter installed only into a private imported copy of the pinned build supervisor. Never change the generic original file. Replace that private module's _wait_run with a compiler-only hook; leave creation, suspended assignment, launch, shutdown, log readers, typed APIs, durability and close handling unchanged. No native API/filesystem/process actions at import or install.

Only one root and kill_on_close are supported by this adapter. Reject inconsistent records rather than generalizing it to ordinary workers, asynchronous launchers, production processes or multiple workers. The admitted caller still pins the exact CMake batch command, compiler tools, source, adapter, supervisor and admission. It checks compiler-root outcome and cleanup independently before admitting DLLs.

The hook signature matches the pinned _wait_run. Use its supplied dependencies and already-owned root process handle. Check cancellation, stream overflow or bad_read, and monotonic deadline before waits and again before returning success. WaitForSingleObject must be zero for the owned root, not merely an absent PID. WAIT_TIMEOUT keeps waiting with a bounded small sleep; other statuses or exceptions produce UNKNOWN. Query GetExitCodeProcess through that same handle; nonzero is FAILED, exceptions UNKNOWN. Do not inspect or terminate processes by PID/name, reopen process control handles, kill anything inside this wait hook, suppress an exception, or weaken a deadline/log bound.

After a verified zero root exit, return COMPILER_ROOT_EXITED_CLEANUP_REQUIRED with an explicit reason. Do not return PROCESS_COMPLETED. Existing run_workers therefore takes its existing TerminateJobObject/shutdown path. This hook never claims auxiliaries exited naturally, cleanup succeeded, log drain succeeded, DLLs exist, numerical results passed or an arbitrary tree is certified.

A caller may accept a compiler stage only after receiving the explicit compiler-root status, root exit zero with assigned/resumed true, final job_active_count zero, drain_proof CLEANUP, complete bounded log capture with no overflow, no ambiguous handle/read/close state, unchanged input/admission/source/tool pins and verified owned-root reaping. A failed cleanup remains refused. The caller records the different completion semantics and keeps whole_tree_certificate false. No GPU execution is authorized by the adapter.

Supply independent pure tests using injected fake wait/exit/clock/event behavior. Required discriminating controls: root success with auxiliaries still present requests cleanup (not natural completion); nonzero root; root timeout; cancellation before/after exit; log overflow or bad reader before/after exit; unexpected wait/exit query exceptions; wrong worker count or policy. Check exact returned state, cleanup-not-performed-in-hook and no import-time native/process calls. Do not execute the native Windows APIs in these pure tests.

A separately ROOT-admitted native CPU-only fixture must then test one successful root, a successful root with a resident child holding inherited pipes, a failed root, a live root timeout, and cancellation. It must use owned Job/retained-handle cleanup, finite deadlines, tiny bounded memory and logs, exact markers/PID observations, cleanup failure refusal, and source/pin preservation. Plan that fixture; do not launch it from a provider response.

Deliver strict JSON with exactly adapter_source, pure_tests_source, rationale, safety_checks, native_fixture_plan. The first two are bounded complete Python source strings. The other fields are nonempty arrays of strings. No markdown fences, auth/driver/environment/global Factory modifications, live product edits, candidate execution or provider tools. The root will parse, inspect, stage and test separately. No tolerance or workload change is permitted.
