# Primary Vulkan references read during preparation

These notes are source-grounded constraints, not a native protocol acceptance. Retrieved 2026-10-04; the URLs point at the current specification and may evolve.

1. https://docs.vulkan.org/refpages/latest/refpages/source/VkImportMemoryHostPointerInfoEXT.html — Description and host-pointer VUIDs. Repeated imports across instances are permitted, with platform failure possible. The original host pointer may remain usable with synchronization; the backing must outlive imports. Restrictions on undefined imported contents and alternate pointers concern non-host-visible imports. Actual-pointer alignment and allocation extent must be valid.
2. https://docs.vulkan.org/spec/latest/chapters/memory.html — Memory-import discussion; Host External Memory; Host Access to Device Memory Objects. Import preserves contents generally. HOST_COHERENT removes mapped-range flush/invalidate requirements but not device availability/visibility. An original imported host pointer is not a vkMapMemory mapping; original-pointer cache maintenance requires appropriate platform synchronization. Noncoherent handling cannot be silently assumed or enabled by this draft.
3. https://docs.vulkan.org/spec/latest/chapters/synchronization.html — Queue Family Ownership Transfer, particularly current web lines 7341–7380. FOREIGN can represent different devices/drivers; EXTERNAL is narrower. Correct release/acquire ordering and ranges are necessary. Intervening modification cannot be handwaved. Other resource aliases may have undefined contents after transfer; proving that two independently created views are corresponding external resources remains essential. A fence wait alone does not establish that correspondence.

The output must distinguish established specification text from inference. If the corresponding-resource relationship cannot be established, refuse this external ownership protocol. A separately described host-domain fallback must establish its own synchronization and must not inherit the original no-CPU-payload-transfer label without proof.
