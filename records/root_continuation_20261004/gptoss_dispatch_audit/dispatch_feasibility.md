## Minimum scoped adapter

Use a harness-owned queue manifest and per-job directory under `E:\the_harness\records`, with a small isolated supervisor that accepts one explicit task, bounds each owned child, captures logs/usage/status, and writes receipts only inside that job directory. Do not call `todo_autodispatch.main/run_all_cycles`, `auto_second_lens.mint`, or `dispatch_agy.main`, and do not write to Factory `envelopes`, `logs`, `receipts`, or Q-RAG state.

For GPT-OSS, the existing wrapper pattern is a direct, plan-mode `agy.exe` invocation with a strict JSON schema and a task-specific harness working directory. Its answer must be treated only as a candidate choice from a fixed Qwen/Gemini/Grok roster and validated locally before any paid worker call. The direct pattern has worked, but it bypasses current Factory GPT-OSS policy by design. Calling it as a router therefore needs a separately approved GPT-OSS policy/qualification gate; changing or bypassing the existing `NO_OPENAI_POLICY` guard is outside this read-only audit.

For worker admission, reuse the existing exact-model/source-bound qualification contract and provider command validation as design inputs (`lane_qualification.py`, `no_openai_guard.py`), while keeping the queue, receipt paths, and execution supervisor isolated. The Factory APIs cannot be called wholesale without bringing their global task, telemetry, filesystem, and RAG side effects with them. This is feasibility only, not an implementation or a claim that GPT-OSS is currently dispatching work.
