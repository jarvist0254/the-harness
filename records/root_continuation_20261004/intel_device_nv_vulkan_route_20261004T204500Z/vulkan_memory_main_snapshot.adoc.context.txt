2774: [open,refpage='VkImportMemoryFdInfoKHR',desc='Import memory created on the same physical device from a file descriptor',type='structs']
2775: --
2776: To import memory from a POSIX file descriptor handle, add a
2777: slink:VkImportMemoryFdInfoKHR structure to the pname:pNext chain of the
2778: slink:VkMemoryAllocateInfo structure.
2779: The sname:VkImportMemoryFdInfoKHR structure is defined as:
2780: 
2781: include::{generated}/api/structs/VkImportMemoryFdInfoKHR.adoc[]
2782: 
2783:   * pname:sType is a elink:VkStructureType value identifying this structure.
2784:   * pname:pNext is `NULL` or a pointer to a structure extending this
2785:     structure.
2786:   * pname:handleType is a elink:VkExternalMemoryHandleTypeFlagBits value
2787:     specifying the handle type of pname:fd.
2788:   * pname:fd is the external handle to import.
2789: 
2790: Importing memory from a file descriptor transfers ownership of the file
2791: descriptor from the application to the Vulkan implementation.
2792: The application must: not perform any operations on the file descriptor
2793: after a successful import.
2794: The imported memory object holds a reference to its payload.
2795: 
2796: Applications can: import the same payload into multiple instances of Vulkan,
2797: into the same instance from which it was exported, and multiple times into a
2798: given Vulkan instance.
2799: In all cases, each import operation must: create a distinct
2800: sname:VkDeviceMemory object.

2817:   * [[VUID-VkImportMemoryFdInfoKHR-handleType-00670]]
2818:     If pname:handleType is not `0`, pname:fd must: be a valid handle of the
