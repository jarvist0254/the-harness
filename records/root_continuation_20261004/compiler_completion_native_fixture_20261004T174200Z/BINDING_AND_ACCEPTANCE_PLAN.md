# Native CPU fixture proposal — not run

This proposal follows the actual compiler-only specification. No adapter API is assumed. The driver placeholder returns NOT_CHECKED and does not import or execute any candidate.

The resident-child control is deliberately different from a naturally draining child: the root creates a Python child without breakaway, explicitly inherits its stdout and stderr, waits for the child to publish both markers and an atomic readiness record, then exits zero or three while that child sleeps for 60 seconds. The supervisor must use its owned Job shutdown to close the inherited pipes within its cleanup bound. Returning a compiler-root label without verified cleanup must fail this control.

Before a future driver exists, ROOT must supply the actual reviewed adapter file, hash and installation symbol. The future case controller checks exact hashes of the interpreter, private FA907 source, adapter, its own source, worker, case contract and external root admission before importing either module. It snapshots these pins again after execution. Import/install purity and the actual adapter pure tests are separate prerequisites. No native work is authorized by this proposal.

Each of five cases runs in a newly created native_runs/<run>/<case> directory, with a unique one-root version1 manifest, startup1 second, log4096 bytes per stream and kill_on_close. The API receives a caller-owned threading.Event. Cancellation starts only after the owned root's atomic READY record is observed, then waits0.1 seconds; it must exercise a running root rather than accidentally cancelling before creation. Readiness polling itself is bounded by1 second and must refuse a missing/mismatched record.

A future outer driver retains its case-controller Popen handle, captures finite logs, bounds each case to15 seconds and the entire suite to60 seconds, and stops immediately on native uncertainty or source mismatch. Killing only that retained controller on an outer timeout is emergency refusal, not a cleanup PASS or arbitrary controller-loss certificate. The existing base has8 seconds of shutdown budget. Source-only timing estimates are not measured performance.

For both successful cases the raw custom status, assigned/resumed root, actual root exit0, final job_active_count0, CLEANUP, bounded complete logs, unchanged pins and durable matching restart receipt are all required. The failed resident case requires FAILED/nonzero_exit and actual root3 with the same cleanup evidence. Timeout and cancellation require their exact terminal states and retained-root termination evidence; neither may remain STILL_ACTIVE. All cases retain whole_tree_certificate=false and no replay/reattach. A generic PROCESS_COMPLETED label cannot substitute for the explicit compiler-root policy.

Parse marker JSON with duplicate-key rejection. Require exactly one own-root marker per stream and, for resident cases, one own-child marker per stream. Their IDs must bind to supervisor root PID, root-created child PID and atomic child READY file. Extra/missing/truncated markers, overflow, bad readers, uncertain closes or missing cleanup evidence refuse the case. After Job cleanup, use only bounded read-only PID-presence checks on these observed owned PIDs; never reopen a PID for process control or kill by name.

The worker allocates no model buffers and starts at most one Python child. Its fixed fixture payload is tiny; ordinary interpreter memory overhead has not been measured or certified. No external compiler/application, GPU, global environment change, real native run, or broad tree certification is included.
